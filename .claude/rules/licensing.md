# Licences and notices

- **`LICENSE.txt` is MIT and nothing else; the rbs notice lives in `NOTICE.txt`.** They were one
  file split on a `---`, and the cost was measurable: `cargo about` could not recognise the appended
  file as MIT, so ya-lsp's own crate was filed under a generic template instead of its own copyright
  line. GitHub's detector works the same way. A test asserts `LICENSE.txt` has no `---` and no
  `Soutaro`; CI asserts the same of the copy inside the VSIX.

- **`NOTICE.txt` covers both pieces of rbs material and is the only place the copyright holder is
  named.** One is the vendored signatures `build.rs` embeds; the other is the `ruby-rbs` /
  `ruby-rbs-sys` crates that compile rbs's C parser in. Same holder, same licence, one notice.
  `THIRD-PARTY-NOTICES.txt` does **not** substitute: `cargo about` walks only the Cargo graph, so it
  never sees the signature files, and neither rbs crate publishes a licence file to harvest — the
  generated file reproduces the SPDX template with its unfilled `Copyright (c) <year> <owner>` line.
  Delete `NOTICE.txt` and no artifact names Soutaro Matsumoto anywhere.

- **`NOTICE.txt` reproduces `vendor/rbs/BSDL` and `COPYING` verbatim, and a test enforces it.** It is
  hand-written, holding copies of two files a `vendor/rbs` bump can rewrite; a drifted copy is a
  licence nobody granted. Re-assemble it from the files rather than editing the text in place. A
  second test pins the rbs version named in it.

- **The rule is per artifact, not per repository.** `ya-lsp --licenses` (`src/licenses.rs`)
  concatenates all three files, so a bare binary attached to a release, rehosted, or installed with
  `cargo install` is self-contained. The VSIX ships all three (the Marketplace shows the licence and
  nobody runs `--licenses` on an extension); the standalone `.tar.gz` / `.zip` ship them beside the
  binary. Each is checked in CI, in the shell of the platform that built it. `licenses.rs` used to
  parse `LICENSE.txt` apart on its separator; it now `include_str!`s three files.

- **`THIRD-PARTY-NOTICES.txt` covers the ~100 crates linked into the binary.** Generated by
  `cargo about` from `about.toml` + `about.hbs`, **committed rather than generated at build time** so
  `cargo build` and `cargo install` need no extra tool. `make notices-check` regenerates and diffs it
  byte for byte; both workflows run that target rather than spelling it out.

- **It is checked in two workflows because the triggers do not overlap.** `ci.yml` runs on pushes to
  main/master and on pull requests; a tag push fires neither. So `release.yml` has a `notices` job
  that `vsix` needs — otherwise a tag cut from a commit CI never saw ships twelve artifacts carrying
  a notice that omits a dependency, on the one path where nothing can be corrected afterwards.

- **`cargo-about`'s version is pinned once, in the `Makefile`**, installed by `make setup-notices`.
  `about.toml`'s `accepted` list is ordered — the first entry matching a crate's expression is the
  licence elected, which is why `MIT` leads `Apache-2.0`.

- **The repository holds the only copy of `THIRD-PARTY-NOTICES.txt`, `NOTICE.txt` and
  `CHANGELOG.md`.** The extension's `vscode:prepublish` runs `stage-shared`, so every `vsce package`
  gets all three without a separate step, and a missing root file fails packaging rather than
  shipping a VSIX without the notice. `editors/vscode/.gitignore` lists the staged copies so nobody
  edits one and loses it at the next package. It copies through `node -e`, not `cp`, because two of
  the six release runners are Windows. The changelog rides along for the same per-artifact reason;
  `vsce` lowercases it to `changelog.md`, which is what the Marketplace reads for its Changelog tab.
